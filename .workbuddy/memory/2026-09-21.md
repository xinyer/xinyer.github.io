# 2026-09-21

## 把《猜瓶子》《记忆卡片》两个小游戏发布到博客（游戏分类）+ 修好自动部署链路

**需求**：两个独立 HTML 小游戏（当时只存在于 `_site/posts/猜瓶子/`、`_site/posts/记忆卡片/`）
要挂到 categories 的「游戏」目录下，能直接打开玩，并部署上线。

### 关键发现：`_site/` 是构建产物，不能当源码用
- `.gitignore` 里就有 `_site`，`git ls-files _site` 为 0 → 放在 `_site/` 里的游戏**下次构建即丢**。
- 站点的 HTML 由 GitHub Actions（`bundle exec jekyll b`）生成，不是分支直出。

### 落地结构（沿用仓库既有约定）
- 游戏资源放 `assets/games/<slug>/`（与 2048/flappybird/spaceshooter/waveshoot/gobang 一致），
  目录名用英文 slug：`guess-bottle`、`memory-cards`（相对引用保持原样即可，无需改代码）。
- 文章 `_posts/YYYY-MM-DD-game_<slug>.md`，`categories: [游戏]`，
  `slug` 由**文件名**决定（不是 front matter 的 title）→ 落地地址 `/posts/game_guess_bottle/`。
- 正文 = 「全屏打开」链接 + `<iframe src="/assets/games/<slug>/index.html"
  style="width:100%;height:80vh;min-height:620px;border:0;border-radius:12px">`。
  比 2048 那种固定 480×1040 更适合响应式页面。
- 复制时排除 `tests/`、`_dev/`、`.workbuddy`、`assets/avatars/_raw/`、`.DS_Store`（`_` 开头的目录 Jekyll 本就会忽略）。

### ⚠️ 自动部署从 2024 年起就一直是坏的
- 症状：Actions 的 `build` 在 **"Set up job"** 步骤就失败（不是编译失败），
  注解写着 `uses a deprecated version of actions/upload-artifact: v3`。
- 根因：`actions/upload-pages-artifact@v1` 内部依赖已被 GitHub 强制停用的 `upload-artifact@v3`
  （2024-04 起自动判失败）。**新版必须 ≥ v2/v3。**
- 修法：整个工作流升级到当前版本 —— `checkout@v4` / `configure-pages@v5` /
  `upload-pages-artifact@v3` / `deploy-pages@v4`（`ruby/setup-ruby@v1` 不用动）。
- 推论：workflow run 历史有 90 天保留期，**run 列表为空 ≠ 没跑过**；
  `deployments` 记录（environment `github-pages`）不会被清，可用来判断历史上是否成功部署过。

### ⚠️ htmlproofer `--check-html` 的 ImageCheck 会卡住 CI
- **空 alt（`alt=""`）也算不合格**（源码判据：`alt.nil? || alt.strip.empty?`），
  会报 `image ... does not have an alt attribute` 并以 exit 1 结束 → `deploy` job 被 skip。
- 仓库里本来就有一处（`_posts/2023-03-02-android-performance-metrics.md` 的 `metrics-anr.png`），
  顺手补了 alt。新游戏的 `#roleAvatar` / `#modalAvatar` 也从 `alt=""` 改为有意义文案。

### 本地复现 CI 的方法（Ruby 2.6 系统版可用）
```bash
bundle config set --local path vendor/bundle
bundle install                                  # 会拿到 chirpy 6.2.3 + jekyll 4.3.4
JEKYLL_ENV=production bundle exec jekyll b
bundle exec htmlproofer _site --disable-external --check-html --allow_hash_href
```
注意 `Gemfile.lock` 在 `.gitignore` 里（CI 每次重新解析最新版本），
`bundle install` 会改写它但不影响提交。管道后取 `$?` 拿不到 htmlproofer 的退出码，要重定向到文件再取。
