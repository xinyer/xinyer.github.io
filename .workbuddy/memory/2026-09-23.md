# 2026-09-23

## 记忆卡片小游戏：修复「点不开下一张」交互死区

文件：`assets/games/memory-cards/js/game.js`、`js/main.js`（同步到 `_site/assets/games/memory-cards/js/`）

**症状**：翻开一张卡片（点错、正面朝上）后，点其他背面卡片没反应。

**根因（两个叠在一起）**：
1. `game.pick()` 里 `if (this.locked || this.finished) return null` —— 点错后的 `peekMs`(780ms)
   错误展示期内，所有点击被直接吞掉。
2. 更隐蔽：`sweepBack()` 的收尾计时器 `cards.forEach(remove 'is-open')` 在 ~800ms 后无差别清掉
   所有卡片的翻开态。此时 `locked` 已是 false，玩家抢在这段时间点开的新卡片会被它一起翻回去。

**修复**：
- `game.js`：新增 `_flushSweep()`（清计时器 + `sequence=[]` + `locked=false` + 发 `sweep` 事件
  `{instant:true}`）；`pick()` 改为「点已翻开的忽略 → 若 `locked` 则先 `_flushSweep()` → 按全新第一次
  判定」，彻底去掉死区。`sweep` 事件统一改为 `{instant, snapshot}` 结构。
- `main.js`：新增 `settleClosedCards()`（以 `game.isOpenAt(i)` 为准对账 DOM 类名）；`flip` 事件里
  `clearSweepTimers() + settleClosedCards()` 打断旧动画；`sweepBack(instant)` 抢拍时不做错峰、
  不刷状态文案、不加 sweep 音效。停手不动时仍保留原有「停留 780ms → 错峰倒带回放」的观感。

**验证**：Node 逻辑回归 17 条 + 无头 Chrome DOM 时序探针 15 条全绿（S1 抢拍 / S2 停手自动翻回 /
S3 倒带动画中抢点 / S4 抢拍后仍能通关），并断言「DOM 类名 ↔ 游戏状态」始终一致。

**注意**：`_site/` 是 Jekyll 构建产物，改源码后要手动同步这两个 js（本次已同步）。
