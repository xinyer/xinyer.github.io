## 记忆卡片小游戏：修复「点不开下一张」交互死区

文件：`assets/games/memory-cards/js/game.js`、`js/main.js`（同步到 `_site/assets/games/memory-cards/js/`）

**症状**：翻开一张卡片（点错、正面朝上）后，点其他背面卡片没反应。

**根因（两个叠在一起）**：
1. `game.pick()` 里 `if (this.locked || this.finished) return null` —— 点错后的 `peekMs`(780ms)
   错误展示期内，所有点击被直接吞掉。
2. 更隐蔽：`sweepBack()` 的收尾计时器 `cards.forEach(remove 'is-open')` 在 ~800ms 后无差别清掉
   所有卡片的翻开态。此时 `locked` 已是 false，玩家抢在这段时间点开的新卡片会被它一起翻回去。

**修复**：
- `game.js`：新增 `_flushSweep()`（清计时器 + `sequence=[]` + `locked=false` + 发 `sweep` 事件
  `{instant:true}`）；`pick()` 改为「点已翻开的忽略 → 若 `locked` 则先 `_flushSweep()` → 按全新第一次
  判定」，彻底去掉死区。`sweep` 事件统一改为 `{instant, snapshot}` 结构。
- `main.js`：新增 `settleClosedCards()`（以 `game.isOpenAt(i)` 为准对账 DOM 类名）；`flip` 事件里
  `clearSweepTimers() + settleClosedCards()` 打断旧动画；`sweepBack(instant)` 抢拍时不做错峰、
  不刷状态文案、不加 sweep 音效。停手不动时仍保留原有「停留 780ms → 错峰倒带回放」的观感。

**验证**：Node 逻辑回归 17 条 + 无头 Chrome DOM 时序探针 15 条全绿（S1 抢拍 / S2 停手自动翻回 /
S3 倒带动画中抢点 / S4 抢拍后仍能通关），并断言「DOM 类名 ↔ 游戏状态」始终一致。

**注意**：`_site/` 是 Jekyll 构建产物，改源码后要手动同步这两个 js（本次已同步）。

## 记忆卡片排行榜持久化现状（已核实，无需再查）

用户问「把排名信息存到浏览器本地」——**已经实现了**，不用改代码：

- `js/leaderboard.js` 用 localStorage，键 `memory-cards:records:v1`，结构
  `{ <模式>: { <角色id>: { bestTime:{ms,misses,at}, bestMiss:{ms,misses,at} } } }`，
  模式为 `easy / hard / hell`；旧扁平结构加载时自动迁移到 `easy`。
- 另两条键在 `main.js`：`memory-cards:last-role:v1`、`memory-cards:last-mode:v1`（记住上次选的角色与难度）。
- **排名不单独落盘**，`rankingTime() / rankingMiss()` 每次从存储实时排序；写入只发生在通关
  `board.submit()`（读最新 → 取更优 → 写回，所以多开标签页也基本不会互相覆盖）。
- localStorage 不可用/写失败 → 静默降级为内存兜底，`board.isPersistent()` 可查。

实测方式（同一 Chrome `--user-data-dir` 跑两次）：`?screen=game&win=1&dump=1` 拿到 `boardRows=1`，
第二次加载 `?screen=game&dump=1` 仍是 `boardRows=1` → 确认刷新不丢。

## 记忆卡片：修复「每次刷新都要重选星球」

文件：`assets/games/memory-cards/js/main.js`（已同步 `_site/assets/games/memory-cards/js/main.js`）

**⚠️ 更正上一节的结论**：`memory-cards:last-role:v1` 这个键**确实存在、也确实有写入**
（`selectRole()` 里写），`currentId` 启动时也会从它恢复 —— 但**界面层始终把选择挡回去了**，
所以用户感受就是「没记住」。**光看存储层代码会误判成已实现。**

**根因**：启动分支无条件弹选角页 ——

```js
} else if (!autoPlay && wantScreen !== 'game') {
  openSelect();   // 正常流程：开局先选角色
}
```

**修复**：
- 新增 `hasSavedRole = !!(lastRole && charById[lastRole])`（存档里的角色还必须仍存在于角色表，
  否则界面会停在一个不存在的选项上）；`currentId` 改用它。
- `?role=xxx` 生效时置 `rolePinned = true`（显式指定视同已选好，且**不写存储**，保持调试参数无副作用）。
- 启动分支改为 `... && !(hasSavedRole || rolePinned)` 才 `openSelect()`。
  首次访问仍有引导页；老用户直接进牌桌，顶部头像/`?screen=select` 仍可换星球。
- 调试参数注释补上 `?screen=game`，并把 `?role=` 标注为「跳过选角页」。

**验证**：同 profile 连续 9 次加载（无头 Chrome + `--user-data-dir`）全绿 ——
①空档仍弹引导 ②真人点火星→存档=mars ③★刷新后**不再弹引导**、星球=mars ④刷新后卡片能点开
⑤`?screen=select` 仍可打开 ⑥`?role=neptune` 生效且不挡路 ⑦刷新后未污染（仍 mars）
⑧改用木星→存档覆盖 ⑨★刷新后记住木星。

**教训**：验「记住上次选择」这类需求，不能只看存储读写代码，也不能只跑一次加载 ——
必须用同一个 `--user-data-dir` 连续多次加载走完整链路。已把这张 7 步检查表补进
`canvas-game-visual-verify` skill 的 7.5 节。

## 记忆卡片：页内难度切换 + 榜单全难度混排 + 按难度换卡背配色

文件：`assets/games/memory-cards/` 的 `index.html`、`css/styles.css`、`js/main.js`、`js/leaderboard.js`
（四份都已同步到 `_site/assets/games/memory-cards/`）

### 1）难度可在游戏页内切换
- `index.html` 在 `.hud` 与 `.playfield` 之间新增 `<section class="difficulty" id="difficulty">`，
  `.diff` 样式与选角页 `.mode` 同源（tone 圆点取自 `Problems.MODES[].tone`）。
- `main.js` 新增 `renderDifficulty()` / `syncModeUI()`；`selectMode()` 只改状态与界面，
  **本局是否重洗由调用方决定** —— 页内切换的点击处理里补 `game.reset()`（牌面按难度生成，不重洗会新旧混着）。
- ⚠️ 难度控件**只建一次 DOM**，之后只切 `is-active`/`aria-checked`（`syncModeActive()`）。
  最初写成每次 `innerHTML=''` 重建，导致按过的按钮被换掉、键盘焦点丢到 body，同时让探针缓存的
  NodeList 失效（3 条断言假失败）。

### 2）榜单不区分难度
- `leaderboard.js`：**存储仍按难度分开**（`{easy:{id:{bestTime,bestMiss}},hard:...,hell:...}`，
  因为要记住每条成绩出自哪档），但榜单改为 `collect(field, compare, onlyMode?)` 聚合：
  同一角色命中多档时按规则只留最优那条，行上带 `mode` 字段。
  `rankingTime()` / `rankingMiss()` 不传 mode = 全难度混排；新增 `bestOf(id)` 返回
  `{time, miss}`（时间和失误的最优可能来自不同难度，所以是两条而不是一条）。
- `main.js` 的 `renderBoard()` 每条加 `.board__diff` 难度标签（薄荷/琥珀/珊瑚三色），
  头部徽标与空态文案改为「全部难度 / 还没有成绩」。
- `?seed=1` 改为**三档难度都铺**示例成绩，且刻意让「谁最强」随难度变化，
  这样榜首的难度标签才会出现三种（全塞简单档会清一色「简单」，看不出标签有没有生效）。
  seed 后补了一次 `renderRoles()` —— 它在启动时已渲染过，不补刷截图里会显示成「暂无成绩」。

### 3）卡背按难度换色
- `styles.css` 把卡背硬编码的草地绿抽成 `--back-top/mid/deep/inset/drop/emblem`，
  默认（简单）= 绿，`html[data-mode="hard"]` = 蜜橙琥珀，`html[data-mode="hell"]` = 珊瑚红。
  JS 只需 `document.documentElement.dataset.mode = currentMode`。
- ⚠️ **没用 `color-mix()` 派生阴影色**：微信内置浏览器等老 WebView 不支持，七个色值全部显式写出。
- ⚠️ 别漏掉 `@media (hover:hover)` 里 `.card:not(.is-open):hover .card__face--back` 的那组阴影，
  它原先也写死了 `--grass-deep`，不改的话桌面端悬停时会在橙/红卡背上闪一下绿色。
- `--grass-*` 保留给场景草地，不受难度影响。

### 实测结论
- 内置 `?selftest=1` 全绿；注入探针 18 条断言全绿（混排排序/标签命中/三档标签色互不相同/
  页内切换后牌面与背色同步/难度写入 last-mode）。
- 几何：`?dump=1` 里新增 `difficulty` 盒子，无横向溢出、卡牌无重叠。
- ⚠️ **已知边界**：新增难度行占 47px，视口高 < ~630px 时状态行会被挤到首屏外
  （实测 vp=557 时 status 底边 591 溢出，vp=637 就正常了）。
  ≥ iPhone SE(667) 都没问题，且页面本来就可滚动（榜单一直在首屏外），故未做压缩。
- 窄屏必须用**固定尺寸同源 iframe 壳**才测得到（无头窗口有 500px 下限）：
  390px 下 `.roles` 变 2 列、角色卡 153px，`最快 10.8s` 这类文案**完整显示无截断**
  （更早看到的「最快 10....」是我 LANCZOS 放大图片的错觉，DOM 里 `scrollWidth === clientWidth`）。
- 顺带把空态文案 `还没挑战过` → `暂无成绩`（更短、更稳）。
